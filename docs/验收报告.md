## 五、交接版发现并修复的问题

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | 官网嵌入的是旧版地址 `docs.google.com/spreadsheet/pub?key=…`，原代码只认 `/spreadsheets/` | **官方数据完全无法发现** | 两种格式都支持，有真实页面片段测试 |
| 2 | Google CSV 用 CRLF 换行，Swift 把 `\r\n` 当作一个字符，原解析器整表读成一行 | **官方数据完全无法解析** | 先统一换行符，有回归测试 |
| 3 | Stooq 已加 JS 人机验证；Yahoo 对部分 IP 限流 | 行情可能全部失败 | 改为 Yahoo → Nasdaq → Cboe 三家依次尝试，同一次评分只用同一家 |
| 4 | 比率窗口不检查交易日是否连续；过期只警告不阻断 | 可能用缺行或过期数据评分 | 加入 NYSE 日历；窗口必须连续；落后 ≥2 个交易日阻断等级 |
| 5 | 官网页面限流时整体失败 | 可用性差 | 重试，并改用已发现或已核实的官方表格地址，界面明确提示 |
| 6 | 构建脚本只编当前架构；没有 DMG | — | 通用二进制，同时出 ZIP 和 DMG |
| 7 | 只读“发布到网络”这一个渠道（有缓存）。2026-11-12 用户发现官网页面显示 387/127，App 显示 394/129 | 用户无法判断哪个对 | 同时读实时版（gviz）和发布版：以实时版为准，不一致时用红色横幅提示“官方数据正在修订”。实测 11:24 UTC 时实时版、发布版、export 全部为 394/129，用户页面上的 387 是嵌入页面缓存的旧值 |

## 六、未解决问题与限制（如实说明）

1. **没有在你自己的 Mac 上实测**：构建和启动是在 GitHub 的 macOS 15.8.2 实机上完成的。你的电脑（macOS 版本未知）首次打开需要手动放行。
2. **15 分钟自动刷新、睡眠唤醒、跨收盘周期发现新交易日**：只做了代码层面的保证，没有长时间运行实测。建议你开着应用跨一个美股收盘，确认交易日能自动更新。
3. **深色模式**：界面固定为浅色，没有做深色适配。
4. **第三方源（Stage2Stocks）**：页面能访问，但没有验证解析结果；选它时一律不发布等级。
5. **数据源没有服务保障**：Blogger、Yahoo 都实际出现过 HTTP 429；Cboe 晚一天。限流或改版时应用会显示失败或 N/A，不会编造数据。
6. **评分阈值没有回测**；规则审查建议（T2108 过热上限、MA10/MA20 过滤）见 `数据源与评分规则.md` 第四节，等你确认后再改。
7. **签名与公证**：需要 Apple Developer Program 账号（Developer ID 证书 + notarytool）。本次交付只是 ad-hoc 签名。
